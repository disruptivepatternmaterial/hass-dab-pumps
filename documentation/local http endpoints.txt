
###
### Bluetooth
###

The following are Bluetooth calls found by @spaco.
The Wifi/Http calls found below are based on these


{"p":"/api/v1/getmainserial","m":"GET"}
{"p":"/api/v1/configure/settings","m":"GET"}
{"p":"/api/v1/getDUMInfo/<serial>/","m":"GET"}
{"p":"/api/v1/configure/paramsDefinitionCompressed?doc=<esy_style>&version=0","m":"GET"}

{"p":"/api/v1/services","m":"GET"}	scan for nearby Wifi Access points

Note: advantage of Bluetooth is is allows for automatic discovery
Note: disadvantage is limited range; Wifi/Http works within entire home network.

###
### Wifi (after physical button press)
###

The following requests are only available after the device button is pressed for 5 seconds.
This activates pairing/local mode, and allows for Bluetooth and Http. The connection stays 
open/alive as long as there is a regular request (tested for 24h with request once per minute).

Have experimented with triggering this button press remotely (via the H2D app).
None of the following actions puts the device in the correct mode:
- 'Reset uC' / 'Reboot' / 'Restart Bridge'
- 'Identify'
- Hard reboot (power off/on)
